## 部署类

### Q1：Docker 部署最小命令是什么？数据存在哪里？

```bash
docker run -d --name zhy-cloud-disk -p 8080:80 \
  -e ZHY_ADMIN_USERNAME=admin -e ZHY_ADMIN_PASSWORD=Admin12345 \
  -v zhy-instance:/app/instance -v zhy-storage:/app/storage -v zhy-mysql:/var/lib/mysql \
  pollybird/zhy-cloud-disk:latest
```

数据在三个命名卷：`app-mysql`（数据库）、`app-storage`（文件实体与本地备份包）、`app-instance`（安装配置）。`docker compose down` 不会删卷，但 `docker volume rm` 会。

### Q2：修改了 ZHY_ADMIN_PASSWORD 为什么没生效？

`ZHY_ADMIN_USERNAME/PASSWORD/EMAIL`、`ZHY_DEPARTMENT_DRIVE` 等**仅首次静默安装生效**，之后写入安装配置/数据库，改环境变量无效。如需改超管密码：用原密码登录后在「个人中心」修改；忘记密码需进数据库处理。部门开关同理（启动时读取，改动需重启服务生效）。

### Q3：首次启动一直起不来 / 健康检查不过？

- 查日志：`./deploy.sh logs` 或 `docker compose logs -f app`；
- 确认端口未被占用（默认映射宿主机 8080 → 容器 80）；
- 确认数据卷所属磁盘空间充足；
- 未安装时 `/api` 业务接口返回 503/`4001` 属正常，`GET /api/ping` 返回 `{"code":0,"data":{"installed":true,...}}` 即就绪。

### Q4：手动部署选哪个数据库？

- SQLite：零配置，适合个人/小团队；
- MySQL/MariaDB：推荐生产，**备份恢复功能开箱即用**；
- PostgreSQL：可运行，但**应用内备份恢复暂不支持**（见 Q14），需自建 `pg_dump` 备份方案。

### Q5：公网部署要注意什么？

前置 HTTPS 反向代理（客户端也用 `https://` 地址连接）；后端 5000 端口保持不对外（容器内已仅绑定回环）；必要时用 `ZHY_CORS_ORIGINS` 收紧跨域；`client_max_body_size` 反代需 ≥2G（镜像内已配好，自建 nginx 注意）。

## 客户端类

### Q6：客户端服务器地址填什么？要加 /api 吗？

直接填 Web 访问地址，如 `http://<服务器IP>:8080` 或 `https://disk.example.com`，**不要带 `/api`**。请求经 nginx `/api/` 反代到达后端，无需单独开放 5000 端口。

### Q7：客户端提示 token 失效/反复要求登录？

JWT access token 默认 2 小时、refresh token 30 天；客户端遇 401 会**自动刷新**。若仍提示：refresh 也过期（超过 30 天未登录）重新登录即可；服务器重装/更换了 `JWT_SECRET_KEY` 也会导致旧 token 全部失效。

### Q8：部门文件一直显示「正被 XX 编辑」锁着？

排他锁 TTL 2 分钟、客户端每 30 秒心跳，编辑器正常关闭后约 60~90 秒自动释放（v1.3.1 修复了残留问题）；客户端崩溃也会由 TTL 过期 + 每 5 分钟清理任务回收。急用时可让**超管/部门管理员**在接口 `POST /api/file/lock/release` 带 `force:true` 强制释放。升级到 v1.3.1 可根治残留问题。

### Q9：同步冲突了怎么办？会丢数据吗？

默认策略 `keep-both`：生成「服务器冲突」副本，两边都保留；可在客户端设置改为 `last-write-wins`（最后修改者胜出，覆盖方数据不保留）。秒传与分片上传均有 MD5 校验，不会写坏文件。

### Q10：客户端占用/临时文件如何管理？

部门网盘双击打开的文件在**临时缓存目录**，保存自动回传、退出客户端自动清理，超期缓存自动删除；本地同步目录内的 `.zhy.part`/`.zhy.meta` 是下载断点临时文件，下载校验完成后自动替换为正式文件。

## 功能与机制类

### Q11：秒传是"别人传过我就不用传了"，那我的空间还扣吗？

扣。秒传省的是**上传带宽与物理磁盘**（同一内容全服务器只存一份物理文件，按引用计数回收），每个用户/部门的**逻辑配额**仍按文件大小照常占用。回收站条目与历史版本同理占配额，彻底删除后才释放。

### Q12：上传 20MB 以下和以上有什么区别？

≤20MB 走整文件通道；>20MB 自动 5MB 分片（并发 3、单片重试 3 次）、24 小时会话内断点续传、单片与整文件双重 MD5 校验。对用户透明，只体现在进度条与中断恢复行为上。

### Q13：删除的文件去哪了？关掉回收站开关会删掉现有数据吗？

默认进入回收站（个人/部门各自独立）保留 30 天。**关闭开关只影响新删除**（直接硬删除），**不清毁回收站存量**，重新打开即可看到历史数据。历史版本开关同理。回收站条目到期由每小时任务自动彻底清除。

### Q14：为什么 PostgreSQL 的备份恢复不支持？

备份依赖数据库快照工具，v1.3.0 实现了 SQLite（文件快照）与 MySQL/MariaDB（`mariadb-dump`/`mysqldump` 自动适配）；PostgreSQL 的 `pg_dump`/`psql` 恢复链路尚未实现，系统会明确返回「暂不支持 PostgreSQL 数据库的备份恢复」（业务码 `3606`），不会误操作。PG 用户请自建 `pg_dump` 定时任务，并同样做好文件实体备份。

### Q15：部门网盘开关在哪改？

安装时决定（Web 向导勾选或 `ZHY_DEPARTMENT_DRIVE=true` 静默安装）。该开关持久化在数据库并在**服务启动时读取**；当前版本的系统设置接口没有提供运行期切换入口（与 README 描述存在出入，以本 Wiki 为准），如需变更建议在安装配置阶段确定，或直接更新数据库 `system_setting` 表的 `department_drive_enabled` 后重启服务。关闭期间部门相关接口统一返回 403/`4030`。

### Q16：为什么有的后缀传不了？

可执行文件/脚本类后缀被安全黑名单拦截（`exe bat cmd sh py js php ...` 等，见 [个人网盘 · 文件类型限制](./02-Personal-Drive.md#文件类型限制)），返回 `3105`。压缩包内不受限。

### Q17：文件夹为什么不能分享、也不能打包下载？

分享与整包下载当前仅支持**单个文件**（返回 `3203` / `4111`）。需要分享一组文件时可先压缩为 zip；需要整目录搬到本地用桌面客户端同步即可。这是产品当前边界，非故障。

### Q18：怎么确认有多少人在线、流量走了多少？

「系统管理 → 监控仪表盘」：5 分钟窗口在线人数、今日与近 7 天上/下行流量、CPU/内存/磁盘与存储统计，30 秒自动刷新；磁盘占用 ≥70% 黄色、≥90% 红色预警。接口口径见 [管理后台 · 监控仪表盘](./05-Admin-Console.md#监控仪表盘)。

### Q19：升级新版本要做哪些准备？

1. 备份：应用内手动备份一次 + `app-storage`/`app-mysql` 卷快照；
2. `git pull && ./deploy.sh update`（或 `docker compose up -d --build`）；
3. 数据库首次启动自动幂等迁移，旧数据不受影响；1.2.0 之前的旧物理文件由每日 blob 收敛任务逐步去重，无需手工处理。
详见 [安装部署 · 升级流程](./01-Installation.md#升级流程)。

### Q20：文件预览不生效/提示插件不支持？

按顺序排查：

1. 「系统管理 → 插件管理」确认对应插件（图片/视频/文档预览）处于**启用**状态；
2. 确认文件后缀在插件支持的类型内（`GET /api/plugin/available?suffix=` 可查该后缀命中的插件）；
3. 被禁用的插件其文件流接口返回 `5102`；换了新插件记得点「注册」重扫描；
4. 物理文件丢失（`3204`/HTTP 410）属于存储层问题，与插件无关。

## 备份与恢复类

### Q21：备份包里为什么没有我的文件？该备份什么？

应用内备份只含**数据库元数据 + 安装配置**；文件实体在 `storage/`（Docker：`app-storage` 卷）。请对存储卷做快照/磁盘级备份，三者配套：`app-mysql`（或应用内备份包）+ `app-storage` + `app-instance`（已含在备份包内）。

### Q22：恢复后为什么要等 2 秒服务才回来？

恢复会整体替换数据库并回写安装配置，进程内连接池与缓存必须重建，因此恢复成功后**进程 2 秒后主动退出**，由守护（Docker 内置 supervisor / systemd / supervisor）自动拉起。裸机前台 `python run.py` 没有守护，需手动重启。恢复前系统还会自动生成 `pre-restore-*` 回滚快照在实例目录。

### Q23：恢复时选择"远端文件名"和"服务器备份记录"有什么区别？

- **备份记录**：按数据库记录 ID 恢复（远端记录由服务端先拉取）；
- **游离本地文件**：恢复后旧备份记录随旧库消失，但 zip 可能还在 `storage/backups/`，按文件名优先在本地找；
- **远端文件名**：本地找不到时从 SFTP/FTP 下载；
- **上传 zip**：拿任意一份备份包直接恢复（最通用）。

### Q24：定时备份时间为什么改了不生效/什么时候真正执行？

调度器**每小时 :17** 唤醒一次，任务内自查「当前小时 == backup_hour 且开关开启」；因此改动**无需重启**但最多延迟到下一个整点 :17 才被感知。若备份目标为远端，第一次执行前建议先「测试连接」。

### Q25：远端备份密码安全吗？测试连接失败怎么办？

密码以 Fernet 对称加密入库（密钥由 `SECRET_KEY` 派生），接口永不回传明文，留空提交=不修改。测试连接失败按 `3603` 排查：主机端口可达性、账号密码、SFTP 是否密码认证、FTP 明文传输仅限可信内网；远端目录不存在会自动创建，但父目录需有写权限。上传失败会保留本地包并在列表标注原因。

### Q26：容器排障有哪些常用入口？

| 命令/操作 | 用途 |
|-----------|------|
| `./deploy.sh logs`（或 `docker compose logs -f app`） | 跟踪全部服务日志（nginx / gunicorn / MySQL / Redis 由 supervisor 托管于同一容器） |
| `./deploy.sh shell` | 进入后端容器排查（检查 `storage/` 目录、备份包、supervisor 状态等） |
| `./deploy.sh status` / `docker compose ps` | 查看容器运行状态 |
| `curl http://127.0.0.1:8080/api/ping` | 健康检查（版本与安装状态） |
| `./deploy.sh restart` | 重启并重新健康检查 |

排障建议顺序：先 `ping` 判断进程存活 → 看日志定位报错 → `shell` 进容器查文件系统与数据库 → 必要时 `restart`。涉及数据损坏时优先走 [备份与恢复](./06-Backup-Restore.md) 的恢复流程而非手工修库。
